# 三理跨直播间用户动态

使用 `https://ukamnads.icu/api/v2/user` 的公开用户查询接口，只采集三理Mit3uri（UID `2030198123`）的记录。覆盖范围和延迟取决于 Danmakus 的采集范围，无法保证收录所有直播间或实时到达。

## 采集与通知

- spider 每 10 秒查询一次，启动 5 秒后开始首轮。通常只请求第一页（50 个直播场次）；整页没有已入库事件时，向后翻页直到遇到已知记录或越过最近一周边界。第一页中已知场次的新弹幕仍会逐条识别。
- 每 15 分钟较深补查最近一周的场次，每天北京时间 07:20 完整补查历史。接口按开播时间排序，周期补查用于发现较早开始的直播中新出现的事件以及延迟补录。补查分页间隔 1 秒，单个 HTTP 请求串行执行，分页之间允许高频查询穿插。
- 接口失败后退避 30 秒至 5 分钟，响应指定更长的 `Retry-After` 时遵守该时长。无新增事件时只读去重，采集状态至多每分钟写一次。
- 首次成功采集建立静默基线；随后只通知基线建立后发生、且在 24 小时内的新增事件。历史补录存档但不补发过期通知。
- 进入直播间事件只记录。其他房间的弹幕、礼物、舰长、醒目留言转发到订阅三理直播间的群，不向被访问主播的订阅群发送。
- 三理本人直播间的弹幕只走现有实时转发，API 记录不重复通知。本人房间中的其他受支持事件仍可通知。
- 每群可分别使用 `关闭功能 本房互动转发`、`关闭功能 外房互动转发`，默认均开启，使用 `打开功能` 恢复、`功能状态` 查询。本房指主播自己的直播间，外房指其他主播的直播间；开关涵盖对应房间的弹幕、礼物、舰长和醒目留言。关闭不影响采集入库和开播通知。关闭期间的新互动不入发送队列，已排队但投递时发现关闭的互动会过期，重新开启后不会补发已跳过的消息。本房实时弹幕也遵守本房开关。
- 转发文案复用“查弹幕”的事件格式，带北京时间和直播间链接。礼物原始价格保存在原始字段里，在单价/总价含义核实前不显示推算金额。

`user_activity` 保存标准化事件及原始 JSON；`user_activity_poll` 保存采集状态；`user_activity_delivery` 保存逐群发送状态。这些表位于 `data/libot.db`，不混入直播 `event` 表，避免影响直播统计。`/查弹幕` 的查询范围保持不变。

去重键包含用户、房间、毫秒时间戳、事件类型、文本和数量，忽略采集者和可能因直播合并变化的场次 ID。分页错误、错误用户、重复分页或未知响应格式会中止该轮，不将半份结果当作完整结果。

bot 每 2 秒投递已入库通知，无在线 bot 时保留队列。每个群独立确认，发送失败后指数退避（30 秒至 1 小时），订阅已取消或变更、通知已过期时不发送。发送成功与数据库确认之间进程崩溃可能重发，无法与 QQ 的远端发送组成原子事务。运行时采用单个 spider、单个 bot 实例。

## 手动检查

```sh
# 只预览最近记录，不写库、不发送消息
.venv/bin/python scripts/poll_user_activity.py

# 执行一轮采集；首次仅建立基线
.venv/bin/python scripts/poll_user_activity.py --apply

# 全部历史补查；不会重发已入库事件
.venv/bin/python scripts/poll_user_activity.py --full --apply

.venv/bin/python -m unittest tests.test_user_activity -v
```

代码加载需要分别重启 spider 和 bot，不需要重启 monitor、capture 或 NapCat。操作线上服务前必须另行获得授权。
